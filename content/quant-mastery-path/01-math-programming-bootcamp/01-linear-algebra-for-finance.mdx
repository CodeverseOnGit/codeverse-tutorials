## Why this chapter exists

Every quant job, whether it's risk, trading, or development, starts
with the same question: **"How much could this portfolio go up or
down, and why?"**

To answer it, professionals don't use anything mysterious. They use
lists of numbers and tables of numbers, and a few simple ways of
combining them. That's all "linear algebra" is: the maths of lists
and tables.

You've probably done this already without the fancy name. If you've
ever worked out a shopping bill (quantity × price, added up), you've
done the most important operation in this entire chapter.

**You do not need any prior finance or maths beyond school
arithmetic.** Every term is explained the first time it appears, and
every formula is worked out by hand on tiny numbers before we touch
any code.

## What you'll be able to do after this chapter

- Explain what a portfolio, a return, and a weight are, in plain English
- Calculate a portfolio's return by hand
- Measure how "bumpy" an investment is (volatility)
- Explain why owning two different things is usually safer than owning one
- Read a small covariance table without being scared of it
- Run a short Python script that calculates portfolio risk

## Words you'll see (a mini glossary)

You can come back to this box whenever a word feels fuzzy.

- **Asset**: something you can own that has a price, like a share of Apple or a bond.
- **Return**: how much an asset's price changed, as a percentage. If it goes from £100 to £102, the return is +2%.
- **Portfolio**: all the assets you own, together.
- **Weight**: the share of your money in each asset. 60% in Apple means Apple's weight is 0.6.
- **Variance / volatility**: how much returns bounce around. Volatility is the version people talk about out loud.
- **Covariance**: whether two assets tend to move together or not.

## 1. A vector is just a list of numbers

Imagine a shopping list: 3 apples at £2 each, 2 loaves of bread at £3 each.

| Item | Quantity | Price |
|---|---|---|
| Apples | 3 | £2 |
| Bread | 2 | £3 |

The quantities are a list: `[3, 2]`. The prices are another list:
`[2, 3]`. In maths, a list of numbers like this is called a
**vector**. That's the whole definition.

To find the total bill, you multiply matching entries and add them up:

```
3 × 2 + 2 × 3 = 6 + 6 = 12
```

This "multiply matching entries, then add" move has a name too: the
**dot product**. You just did one.

**Why it matters**: nearly every number in portfolio finance, from
total return to total risk, is a dot product or a close cousin of
one. If you're comfortable with the shopping bill, you're already
comfortable with the core idea.

---

## 2. Your first portfolio: weights and returns

Now swap the shopping list for investments.

Say you put **60%** of your money in Stock A and **40%** in Stock B.
Those shares are your **weights**:

```
weights = [0.6, 0.4]
```

Today, Stock A went up 10% and Stock B went down 5%. Those are the
**returns**:

```
returns = [0.10, -0.05]
```

Your portfolio's return is the dot product, exactly like the
shopping bill:

```
0.6 × 0.10  +  0.4 × (-0.05)
=  0.06     +  (-0.02)
=  0.04
```

**Your portfolio gained 4% today.**

Two quick rules to remember:

- If you're fully invested, your weights add up to **1** (that is, 100%).
- A bigger weight means that asset has more influence on your result.

### The same thing in Python

You don't need to be a programmer for this chapter. Here's the same
calculation in four lines, with every line explained.

```python
import numpy as np                 # numpy is Python's tool for lists and tables of numbers

weights = np.array([0.6, 0.4])     # our weight vector
returns = np.array([0.10, -0.05])  # today's returns

print(weights @ returns)           # the @ symbol means "dot product". Prints 0.04
```

## 3. A table of numbers is a matrix

One day of returns is a list. But real data covers many days and many
assets, which makes it a table. A table of numbers is called a
**matrix**.

Here are five days of returns for three assets:

| Day | Asset A | Asset B | Asset C |
|---|---|---|---|
| 1 | +1.0% | +2.0% | -1.0% |
| 2 | -2.0% | +1.0% | 0.0% |
| 3 | +1.5% | 0.0% | +2.0% |
| 4 | 0.0% | -1.0% | +1.0% |
| 5 | +2.0% | +1.5% | -0.5% |

This is just a spreadsheet:

- **Rows** go down, one per day.
- **Columns** go across, one per asset.

We describe its size as **rows × columns**, so this table is
**5 × 3** ("five by three").

**A habit worth building now**: whenever you see a table of numbers,
ask yourself, "What does each row mean? What does each column mean?"
Mixing those up is one of the most common mistakes in quant work, and
it usually doesn't produce an error message. It just produces a wrong
answer.

## 4. How bumpy is an investment? (Volatility)

Two investments can both average +1% a day and still feel completely
different. One creeps along steadily. The other lurches up and down.
We want a single number for "how lurchy". That number is
**volatility**.

Let's calculate it by hand for one asset. Its returns over five days
(in %): `2, -1, 3, 0, 1`.

**Step 1: find the average.**
(2 − 1 + 3 + 0 + 1) ÷ 5 = **1**

**Step 2: see how far each day was from the average.**
`2−1=1`, `−1−1=−2`, `3−1=2`, `0−1=−1`, `1−1=0`

**Step 3: square each gap** (this makes everything positive, so ups and
downs don't cancel out): `1, 4, 4, 1, 0`

**Step 4: add them up and divide by 4.**
(1 + 4 + 4 + 1 + 0) ÷ 4 = **2.5**. This is the **variance**.
(We divide by 4 instead of 5 because of a small technical correction
that statisticians use for samples. For now, just trust it.)

**Step 5: take the square root.**
√2.5 ≈ **1.58%**. This is the **volatility** (also called the
**standard deviation**).

So this asset's daily return typically lands within about 1.6% of its
average. A higher number would mean a lurchier ride.

**Why do we need both variance and volatility?** Variance is easier to
do maths with (you'll see why in section 6). Volatility is easier to
talk about because it's in the same units as the returns.

---

## 5. Do two assets move together? (Covariance)

Volatility describes one asset. But a portfolio has several, and the
interesting question is: **when one drops, what does the other do?**

That's what **covariance** measures:

- **Positive covariance**: they tend to move in the same direction.
  (Two oil companies: when oil falls, both usually fall.)
- **Near-zero covariance**: they mostly ignore each other.
- **Negative covariance**: when one rises, the other tends to fall.
  (Rare, and very valuable.)

We collect all these pairings into one square table called the
**covariance matrix**. For two assets it looks like this:

|  | Asset A | Asset B |
|---|---|---|
| **Asset A** | 0.04 | 0.00 |
| **Asset B** | 0.00 | 0.09 |

How to read it:

- The **diagonal** (top-left to bottom-right, 0.04 and 0.09) holds each
  asset's own variance, so how bumpy each one is by itself.
- The **off-diagonal** numbers (the 0.00s) say how A and B move
  together. Here that's zero, meaning they ignore each other.

You will almost never calculate this by hand. Python does it in one
line:

```python
cov = np.cov(returns_table, rowvar=False)
```

(`rowvar=False` just tells Python "my columns are the assets, my rows
are days". Remember our habit from section 3.)

## 6. Portfolio risk, and why diversification works

Here is the payoff of the whole chapter. Given:

- your **weights** (how much you hold of each asset), and
- the **covariance matrix** (how the assets bump and move together),

the portfolio's variance is:

```
portfolio variance = weights @ covariance matrix @ weights
```

Don't be intimidated by that line. For two assets it expands into
something readable:

```
variance = (wA² × varA) + (wB² × varB) + (2 × wA × wB × covariance)
```

Let's use real numbers. 50/50 portfolio, with `varA = 0.04`
(20% volatility) and `varB = 0.09` (30% volatility).

**Case 1: the assets ignore each other (covariance = 0).**

```
variance = (0.25 × 0.04) + (0.25 × 0.09) + (2 × 0.5 × 0.5 × 0)
         = 0.01 + 0.0225 + 0
         = 0.0325
volatility = √0.0325 ≈ 18.0%
```

**Case 2: the assets move together (covariance = 0.03).**

```
variance = 0.01 + 0.0225 + (2 × 0.5 × 0.5 × 0.03)
         = 0.01 + 0.0225 + 0.015
         = 0.0475
volatility = √0.0475 ≈ 21.8%
```

Same two assets, same weights. The only thing that changed is how
they relate to each other, and the portfolio got about 3.8 percentage
points riskier.

**This is diversification, in numbers.** When assets move
independently, their ups and downs partly cancel out. When they move
together, there's nothing to cancel. That's why "own lots of
different things" is only good advice if they're really *different*.

In Python, the full calculation is:

```python
portfolio_variance = weights @ cov @ weights
portfolio_volatility = np.sqrt(portfolio_variance)
```

## 7. Sneak peek: eigenvalues (optional on a first read)

You'll meet one more idea in later chapters. Here is the only thing
you need to know today.

If you look at a covariance matrix and ask, **"What are the main
independent ways this group of assets moves?"**, the answer comes
from something called **eigenvectors** and **eigenvalues**. A big
eigenvalue means "this pattern of movement drives a lot of the
portfolio's ups and downs."

Risk teams use this to say things like: "80% of our portfolio's
movement comes from one single factor." We'll return to this properly
in Module 6. For now, remember the name and the idea, and move on.

## Common beginner mistakes

1. **Using prices instead of returns.** Prices trend upward over time,
   so any maths on raw prices mostly measures the trend, not the risk.
   Always convert to returns first.
2. **Mixing up rows and columns.** If your table has days down the side
   and assets across the top, tell Python (`rowvar=False`). Otherwise
   it treats each *day* as a separate asset.
3. **Weights that don't add up to 1.** If you meant to be fully
   invested but your weights sum to 0.8, you're accidentally
   describing a portfolio with 20% cash.
4. **Trusting a number just because the code ran.** A script that
   produces a result without errors can still produce a *wrong*
   result. If a number looks unreasonable, investigate it.
